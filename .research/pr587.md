#557's event scheduler on v1.1.34's batched `--parallel`, as discussed in #557.

**The loop runs on events** (`ds4_evt.hpp`). The reader's lines and the turns are events
run one at a time; a line outranks a turn, each turn queues the next as it ends, and with nothing running the loop
waits for a line instead of polling between steps.

**What it schedules:** in v1.1.34 a new request's prompt is read whole while every other conversation waits. Now the
prompts being read take turns, **a piece each** - a chunk per pipeline stage, so a split's GPUs all stay busy - and
every running request writes a token (one `step_multi`) between two pieces. A prompt whole in one piece goes ahead of
the longer reads, so a short question doesn't wait behind them. `MAYA_DS4_READ_ORDER=arrival` keeps v1.1.34's order
for A/B runs.

## Results

3 GPUs (2x RTX 5090 + RTX 3090, layer split), DeepSeek-V4.1-Flash GSQ-RCO IQ2_XXS (about half the experts in RAM),
`--parallel 4`, the same binary for both rows.

**Agent workload** (`tools/ds4/agent_bench.py`: 4 agents x 8 turns at once - 4-12K-token first prompts, tool results of
150-2,000 tokens, one in ten 5-20K, answers of 64-400 tokens, 0.5-5 s of tool time between):

| | First token mean / p50 / p95 (s) | Turn done mean / p95 (s) | Wall (s) |
| --- | ---: | ---: | ---: |
| v1.1.34's reading (`MAYA_DS4_READ_ORDER=arrival`) | 6.14 / 2.55 / 29.1 | 19.98 / 35.2 | 190.6 |
| **a piece each** | **5.23 / 2.37 / 13.5** | 19.98 / 35.5 | 190.5 |

The first token 15% sooner on the mean and **2.2x sooner at p95**; a turn done and the wall the same. A second run of
the default gave 5.22 / 13.5 / 190.4, and the final build (the loop on events) 5.20 / 13.4 / 190.3: v1.1.34 hands
every answer's token back in one call, so the events change the shape, not these numbers - they are what the in-read
gaps (below) build on. Pieces of one chunk were slower (first token 7.13 s, wall 212.1 s): every piece
fills the pipeline again, so a piece is a chunk per stage.

**Real agent traffic** (`--trace`: a 10-minute window of rig's `.served` log, 4 conversations, 73 turns, a turn's new
tokens median 235): a tie, first token 1.91 against 1.86 s, wall 473.5 against 473.6 s. Nearly every turn there fits
in one piece, so pieces and whole reads are the same reads; the gain is where long prompts meet.

## What's in it

- `src/ds4/ds4_main.cpp`: the prompt reader in three steps - `prompt_begin` (pictures, reuse, slots),
  `prompt_piece` (the next tokens, PP lines, a STOP), `prompt_end` (checkpoints). The one-conversation path calls
  them back to back, as before. In `--parallel` a request's prompt is begun at admission and read in turn; a STOP
  while it waits for its turn ends it there and keeps the conversation it continued. A prompt with pictures is read
  whole (the images the model holds are not per conversation).
- `src/ds4/ds4_evt.hpp` (#557's, rig's evt in C++, 140 lines): the `--parallel` loop runs on its events - the
  reader's lines, and the turns (a round of tokens or a prompt's piece), each queueing the next as it ends. A line
  outranks a turn, so every request that came is admitted before the next turn; with nothing running the loop waits
  for a line instead of polling. `Lines::poll` goes (nothing reads between steps any more).
- `Model::prompt_chunk()` and `Model::pipeline_stages()` (the piece's size).
- `docs/SETTINGS.md`: the DeepSeek `--parallel` section.
- `tools/ds4/parallel_test.py` and `tools/ds4/agent_bench.py` from #557 (the checks and the tables above), trimmed to
  this engine.

Each piece is a whole number of the uncut read's chunks, so a prompt reads through the same chunk boundaries as before.

## Tested

- `tools/ds4/parallel_test.py --lanes 4` and `--lanes 2` (greedy): the conversations at once each answer token for token what they
  answer alone; a STOP ends one alone and the other's answer is whole and its own; a kept conversation's next turn
  reuses its lane (2023 of 2032 tokens); a small request sent during a ~100K-token read gets 4 of its 16 tokens before
  the read's last piece (with `arrival` the long prompt is read whole before the small one starts).
- `tools/test_ds4_*.py` and `tools/test_maya_parallel.py`.
- One machine, Linux, 3 GPUs. Not tested: one GPU, tensor parallel, AMD, Windows.
